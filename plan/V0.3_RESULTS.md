## 2. What v0.3 added

- **Durable identity** built from the symbol key the analyzers already produce
  plus a project-relative path. Resolution walks the file and asks each analyzer
  to describe the callables it supports, so it stays language-neutral rather
  than needing a lookup API per language.
- **Flow Pins** as a persistent mark on a callable, drawn wherever that callable
  appears, including inside branch sections and on the entry.
- **Saved Flows** carrying the limits their run used, so opening one reproduces
  that analysis instead of re-running it under current settings.
- **Recents**, written only when a run produced a map, capped at ten, kept in
  the workspace file so a list that reorders every few minutes does not produce
  a commit-worthy diff for a team.
- **Analyze from Here**, resolving the conflict recorded in `V0.1_TASKS.md` §1.
- **A run that accounts for itself**: the callable being analyzed, budget
  consumption, and a summary of why the map stops, where each count selects the
  first card it describes.

## 5. Defects found before the milestone closed

1. **Recording a recent deadlocked the run that produced it.** The entry's path
   was derived on the publishing path, inside a read action, while the caller
   was blocked waiting for that very result. The first analysis recorded and the
   second hung. The path is now resolved when the run starts, on the caller's
   thread, so finishing a run touches no PSI at all.
2. **An acceptance suite passed in isolation and failed in the full build.** The
   light project is shared across test classes, so every analysis any other
   suite had run was already in the recents list. The suite now starts from a
   known state rather than assuming one. This is the same shape as the v0.2
   progress-contract defect that CI caught: a test that reads shared state has
   to say what it expects that state to be.
3. **The status strip's single-row invariant.** Adding the reasons row broke the
   regression test that keeps the summary on one line — correctly, since the
   layout was double-counting row height. The summary now takes whatever the
   reasons row leaves, so hiding the reasons restores the original geometry
   exactly, and both properties are test-locked.

## 6. Decisions recorded

- A **Flow Pin marks a callable**, not a call site or a canvas node. The owner
  chose this over an in-flow reading aid; it is also what the plan's requirement
  for durable identity across refactors implies, since a reading aid would need
  no persistence at all.
- **Saved Flows and "persistent saved entry points"** in `PLAN.md` §17 are one
  feature, not two.
- **Neither Saved Flows nor Recents persist a result.** A result describes one
  source revision and is stale as soon as the file changes, so they store the
  entry point and re-run it.
- **The requested progress bar shows budget consumption**, because an
  exploration has no knowable total. The caveat was stated before building and
  the owner asked for the bar anyway; this is the honest form of it.
