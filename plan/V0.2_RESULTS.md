## 2. What v0.2 added on top of v0.1

- **Structure in the model.** `FlowNode` gained `branches` and
  `sourceSummary`; a structure is one event in its parent's sequence that owns
  labelled sections. Frames stay flat, so nothing else in the engine changed
  shape. Structures consume the node budget but not callable depth.
- **A builder that can be interrupted mid-branch.** `openStructure` /
  `openBranch` / `closeStructure` route events into the innermost open section,
  and `closeOpenStructures` seals whatever is still open so a cancelled or
  truncated run keeps what it found inside a branch.
- **A tree instead of a call list from the analyzers.** `extractDirectFlow` now
  returns `FlowItem`s — calls, structures, terminators — for Java, Kotlin, and
  Go, in evaluation order per `V0.2_SPEC.md` §4.
- **Stacked-section rendering.** One container per structure, a labelled row per
  section, indented events, the sequence resuming below. Keyboard navigation
  walks into sections, so nothing is mouse-only.
- **A disclosure that means something.** `controlFlowIncomplete` is now raised
  only for control flow v0.2 does not model, so it points at a specific
  construct instead of appearing on every branch.

## 6. Defects found before the milestone closed

Eight defects were found and fixed. Every one of them compiled and passed the
tests that existed at the time, which is the recurring lesson of this project:
green tests describe what was thought of, not what is correct.

**Found by the new per-language structure suites**

1. **A Kotlin subjectless `when` dropped its guards.** `walkWhen` walked each
   entry's body but never its conditions, so a call in a `when { cond() -> … }`
   guard vanished from the map — the worst failure mode for this tool, since a
   missing call reads as an absence rather than an error.
2. **A Go loop swallowed its header.** `walkLoop` walked every child into the
   body, putting the range expression and the `for` initializer inside the
   container. Both run once, before the loop.

**Found by CI**

8. **A progress test was only accidentally passing.** It attached its collector
   before starting the analysis, so it also observed the previous run's terminal
   event — the service keeps that value until a new analysis clears it. On CI the
   preceding test left a larger node count, and the "counters never decrease"
   assertion read `[7, 0, 0, 3]`. The service was behaving correctly; the test's
   collection window was not scoped to its own run. Every assertion in that suite
   now filters by the `RunId` that `startAnalysis` returns.

**Found by code review of the milestone**

3. **The structure markers never reached the model.** `StructureSpec` had no
   metadata field, so `closeStructure` built every structural node with an empty
   map. `LOOP_RUNS_AT_LEAST_ONCE` and `SELECT` were produced by the analyzers and
   then dropped: a `do`-`while` rendered as a plain loop and a Go `select` as a
   plain switch. Acceptance cases G and L were passing only because the tests
   asserted at the extraction layer. They now assert on the model and on the card.
4. **The §6 disclosure fired where nothing was hidden.** The spec's own case C
   example, `switch (s()) { case 1: a(); break; }`, was reported as
   control-flow-incomplete, as was `if (s != null && n > 0)`. The disclosure is
   now raised only when a call actually sits in the part that is not represented.
5. **Java `switch` fall-through was never detected**, though the spec, the visual
   design, and the limitations doc all name it as a reason for the warning.
6. **Go dropped calls written in a case label.** A case label's expressions live
   outside the clause's statement list, so the idiomatic tagless
   `switch { case isReady(): … }` and `select { case v := <-recv(): … }` lost
   those calls entirely, and the label text was cut at the first colon so
   `case v := <-ch:` read as `v`. Java `case X when check(i)` and Kotlin `when`
   entry guards were dropped the same way.
7. **A regression in the fall-through fix.** Fixing (5) reported every arrow
   switch as control-flow-incomplete, because a rule-style case carries its body
   where a colon-style case carries statements. Rules cannot fall through at all.
   Caught by the second review pass before the milestone closed.

Defects 1, 2, and 6 are one recurring shape, first seen with Go `getCondition()`
in Milestone 0: a structure's header and its body must partition the source, and
a PSI accessor rarely hands them over as neatly as the syntax suggests. Getting
that partition wrong either duplicates a call or loses one. Per-language
structure suites are what catch it — a shared Java-shaped test would have missed
every instance.

## 7. Layout decision

`VISUAL_DESIGN.md` §13 originally showed a left/right fork. The owner chose
stacked labelled sections on 2026-08-18, and the section now records the
decision and the reason: a fork needs at least two card widths, the tool window
is routinely narrower than that, and a `switch` with several cases would be
unusable. Stacking meets every stated requirement at one card width and scales
to nesting.

## 8. Known limitations recorded

`KNOWN_LIMITATIONS.md` §25–§27 now carry the v0.2 boundaries: structure is not
reachability, the constructs still unrepresented (`switch` fall-through,
`break`/`continue` edges, catch-to-throw routing, short-circuit operands, Go
`select` runtime semantics), and branch labels being truncated source excerpts
that never reach logs.

## 9. Not verified in this milestone

- **Manual sandbox verification** of the new rendering. Per the owner's standing
  instruction, production-IDE checks happen only at v1.0; sandbox verification of
  v0.2 has not been performed at the time of writing.
- **Reachability, `switch` fall-through as an edge, and exception routing**,
  which are out of scope by `V0.2_SPEC.md` §2 and recorded as limitations rather
  than gaps. Fall-through is detected and disclosed; it is simply not drawn.
