## 2. What v0.1 added on top of Milestone 0

- **Settings** (`V0.1_SPEC.md` §19): project-scoped depth, node budget,
  include-tests, include-libraries, with a localized settings UI, a toolbar
  depth control, and an immutable per-run snapshot.
- **Traversal policy** extracted into a pure core function covering origin,
  project location, dispatch, and settings, with an exhaustive unit matrix.
  `Include libraries` is now genuinely honored.
- **Conditional-call semantics**: calls inside branches, loop bodies, catch
  clauses, short-circuit operands, and case clauses are marked, and the canvas
  refuses the certain connector for them. Headers that always run are not marked.
- **Explicit constructor invocation** (`this(...)`, `super(...)`) and Kotlin
  `super.foo()` exact dispatch, both test-locked.
- **Honest indexing stage**: `WAITING_FOR_INDEXES` is published only while the
  IDE is really in dumb mode.
- **UI decomposition** into controller, toolbar, status model/view, selection
  model, details model/panel, and canvas — the two derived-state mappings are
  unit-tested independently of rendering.
- **New canvas states**: `resolving…` for queued frames, an explicit depth-limit
  continuation marker, conditional connectors, and an empty state that lists
  available and unavailable language capabilities with reasons.
- **Re-analysis** from stale/cancelled/failed results, restarting from the
  root's smart pointer so an edit that moved the declaration is handled.
- **Capability catalog** with a drift test in both directions.

## 7. Review findings fixed before completion

An independent high-effort review of the whole v0.1 diff produced seven
findings, all fixed with regression coverage:

1. **Kotlin loop bodies were extracted twice.** `KtLoopExpression.getBody()`
   returns a grandchild, so the identity-based split never filtered the body
   container: every call inside a `while`/`for` became two events, doubling
   cards and node-budget consumption. The same class of bug had already been
   found and fixed for Go; the Kotlin test hid it by collapsing calls into a
   map, so it now asserts the ordered call list.
2. `DumbService.isDumb` was read outside a read action, against its documented
   contract.
3. The settings page bound to a captured `State` instance that `loadState` can
   replace, so an Apply during an external settings change was silently lost.
4. A lagging progress stage could outrank a finished result, leaving a
   completed run looking like it was still running.
5. `do-while` bodies and while-style loop conditions were marked conditional
   even though both always run at least once (Java, Kotlin, Go).
6. An unreachable selection-pruning helper suggested a guard that did not exist.
7. Arrow keys were consumed even when they did nothing, disabling scrolling of a
   wide flow.

Two further defects were found by self-review before that: a resolving
indicator that persisted after a run ended, and a status model that required
both signals to reach a terminal state.

## 8. Continuous integration policy

Hosted Actions minutes are a limited budget on this private repository, so CI
was restructured to be a final gate rather than an iteration loop: draft pull
requests do not run, superseded runs are cancelled, documentation-only changes
are skipped, `buildSearchableOptions` is skipped for ordinary runs, and Plugin
Verifier plus the distribution ZIP run only on explicit request. All of these
checks run locally first, where the full build takes about half a minute and
the verifier about two.

Two hosted runs failed transiently during development; the identical tree
passed on the following run, and the failures coincided with a GitHub incident
that also made the Actions API return 503/404. No code change was required for
them, and none was made on the basis of that failure.
