## 2. What v0.4 added

- **Candidate discovery** through `DefinitionsScopedSearch`, the search the IDE
  runs for Go to Implementation, so Java, Kotlin, and Go are covered by one path
  and a language added later is covered too. On demand, capped, and honest about
  being capped.
- **Dispatch choices**, keyed by callable, held for the session, applied by
  re-running rather than by grafting a subtree onto a finished result.
- **The honesty rule**: a chosen call keeps the dispatch confidence resolution
  gave it, still names the callable that was actually called, and carries a
  separate marker naming whose body is shown. A choice changes what is entered,
  never what the model claims to know.
- **Markdown and Mermaid exports** in `core`, as a pure transformation of the
  model, which is what makes byte-for-byte determinism assertable.

## 5. Defects found before the milestone closed

1. **The first Verifier run was not clean**, for the first time in this project:
   one deprecated call and one scheduled for removal, both introduced by this
   milestone. `Messages.showChooseDialog` is deprecated, and `Query.iterator()`
   — which a Kotlin `for` loop over a query compiles to — is scheduled for
   removal.

   Both were replaced rather than accepted: candidate search now uses the
   `Processor` form, which is also what lets it stop at the cap instead of
   enumerating a whole hierarchy, and the picker is a small `DialogWrapper` with
   room for the sentence that matters — that choosing is not proving. The
   Verifier is back to zero in every category.

   This is what `API_STABILITY.md` exists for: the policy caught a regression on
   the same day it was introduced.

### Found by review

2. **The honesty rule was implemented in the model and nowhere the reader looks.**
   `FlowMetadata.CHOSEN` was read by no UI code at all: the card kept saying
   `Gateway.charge()` with an ambiguous glyph while StripeGateway's body was
   drawn underneath it, headerless, and the details panel never mentioned the
   choice. The model half was correct and well tested, which is exactly what made
   the gap easy to miss — the rule is about what the reader sees. The card now
   carries the chosen implementation as a badge and in its tooltip, and the
   details panel names it as chosen by the reader rather than proven.

3. **The chosen implementation was identified by its bare name**, so
   `chosen: charge()` was byte-identical whether Stripe or Paypal was picked, and
   the export read as though the call had chosen itself. It is now qualified by
   container on both sides. The acceptance test passed on hand-written data the
   production path never produced.

4. **The implementation search ran on the EDT inside a non-cancellable read
   action**, against guardrails §6, with no dumb-mode guard. It now runs through
   `ReadAction.nonBlocking(...).inSmartMode(...)` and opens the dialog when it
   returns.

5. **A choice could not be removed or changed.** `clear` had no production
   caller, and once a choice applied, the card gained a body so the picker's own
   enablement test excluded it. Choices are now listed in the Flows menu with a
   clear action, and a chosen card can be re-opened.

6. **A choice replaced bodies the analyzer could prove.** It applied to any call
   with a matching key, including `DECLARED_TARGET` calls the traversal enters
   normally. A choice now stands in only where the traversal would otherwise
   stop.

7. **Smaller ones**: the chosen marker was recorded even when the body was not
   entered; a stale choice was neither reported nor dropped; Mermaid omitted
   depth limits, test sources, execution modes and the whole stop-reason summary
   that Markdown carries; branch edges emitted inside a subgraph pulled the
   structure node into its own branch; a cycle drew a new node instead of an edge
   back; and both formats emitted raw enum names where the canvas has a localized
   vocabulary.

## 6. Decisions recorded

- **A choice is keyed by callable, not by call site.** That is how the decision
  is made — "in this codebase, that interface is that class" — and a call site's
  identity would not survive the re-analysis a choice triggers. The consequence,
  that two call sites cannot differ, is in `KNOWN_LIMITATIONS.md` §34.
- **Choosing re-runs.** Grafting a freshly analyzed subtree onto a finished
  result would produce a map whose parts describe different source moments.
- **A choice never becomes a proof.** Without this the feature would convert
  honest uncertainty into false certainty, which is the one thing this tool must
  not do.
- **Mermaid sequence and structured-context exports are deferred**, per the
  owner on 2026-08-18. Recorded in `V0.4_SPEC.md` §2 rather than dropped.
